# 架构设计

> 状态：草稿（W1 期间补全）

## 分层职责

### 工具层 — Python / MCP Server

单一职责的工具，每个都能独立测试：

| 工具 | 输入 | 输出 |
|---|---|---|
| `generate_storyboard` | 主题、时长 | 结构化分镜 JSON（镜头数 / 画面 / 台词 / 时长） |
| `generate_frame` | 提示词、镜头号 | 本地图片路径 |
| `generate_video_clip` | 图片、运镜指令 | 本地视频片段路径 |
| `generate_music` | 情绪、时长 | 本地音频路径 |
| `render_video` | 图片/视频序列、音频、字幕 | 成片 mp4 |

### 编排层 — TypeScript / DeepSeek Harness 插件

扩展点（待 W1 确认具体 API）：

- `ctx.tools.register()` — 工具注册
- `tools/pre-execute` / `tools/post-execute` — 调用前门禁、调用后审计与结果变换
- `agent/pre-step` — 上下文注入、状态回填
- 工作流编排 — 多镜头并发、子任务作用域

**编排层承担的可靠性职责：**

- 指数退避重试（区分**随机失败**与**稳定失败**）
- 失败降级（备用提示词模板 / 备用模型，注意风格漂移风险）
- 镜头状态持久化与断点续跑
- 并发限流
- token / 生成次数 / 耗时 → 成本核算

### 服务层 — Java / Spring Boot

- `POST /tasks` 提交任务
- `GET /tasks/{id}` 查询状态
- `GET /tasks/{id}/events` SSE 实时进度
- 任务队列、会话持久化、限流

## 数据流

```
主题
 └─▶ [分镜]  生成结构化 storyboard JSON
      └─▶ [并发] 每个镜头：生图 ─▶ 生视频 ─▶ 质检
           └─▶ [配乐] 按总时长与情绪生成
                └─▶ [合成] 序列 + 音频 + 字幕 ─▶ mp4
                     └─▶ [归档] 产物 + 成本报告
```

## 关键设计决策（持续更新）

| 决策 | 取舍 | 理由 |
|---|---|---|
| 工具用 Python + MCP，而非直接写在插件里 | 多一层进程边界与协议开销 | MCP 是开放协议，工具可跨客户端复用；Python 的音视频生态更成熟 |
| 状态落盘而非只放内存 | 需要处理并发写 | 断点续跑是核心能力，内存态一崩就全丢 |
